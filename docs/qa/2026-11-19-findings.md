## Details

**QA-02.** The printer writes members one per line and the parser closes a body at a line that is exactly `}`. A method body typed or pasted into a class (`+run() {` / `doIt()` / `}`) is enough. On reopen the class closes early, its remaining members become top-level lines ("not understood"), the class's own `}` closes the enclosing package, and the following classes move out of it. The same happens live: the text panel re-reads the whole text after the next keystroke typed in it. The hostile property test found this in most of its failing documents; a member `layout {` after such a `}` even opens a stray layout block that swallows the rest of the file.

**QA-12.** The recovery file name is a hash of the session's path ([app.rs:581](../../crates/umpl-app/src/app.rs#L581)). `save_as` calls `save_to`, which sets the new path, and then `clear_recovery`, which now deletes the copy for the *new* path. The `untitled-….umpl` copy written while the diagram had no path stays, and the next start offers to "recover" work that was saved. Every PlantUML/Umple import has no path, so this hits any import kept open for 30 s before saving. All untitled sessions also share one recovery name, so two windows overwrite each other's copy.

**QA-13.** `recover()` deletes the recovery copy before `request()` decides whether to ask about unsaved changes. With two copies (two crashed windows, or QA-12's leftover), recovering the first makes the session dirty; recovering the second opens the Unsaved prompt, and Cancel loses the second copy for good.

**QA-09.** `write_atomic` writes a new file and renames it over the target. A symlink becomes a regular file (the real file is not updated) and the mode becomes the umask default: a `chmod 600` diagram becomes world-readable after Save.

**QA-11.** `shared_lanes` ([score.rs:116](../../crates/umpl-layout/src/score.rs#L116)) puts every unit grid point of every route into a hash set, and nothing bounds it as the router's draft limit bounds routing. Release `umpl stats` with box B at x = N: 10⁶ → 0.4 s, 10⁷ → 3.8 s, 10⁸ → 54 s then `memory allocation of 2281701392 bytes failed`. A size near `i32::MAX` aborts the same way. `umpl check` reports no problem for these files; a typo in a `layout` line is enough. The GUI repeats the cost on every reroute while dragging.

**QA-14.** PlantUML import follows `!include` with absolute paths to any readable file. Opening an untrusted `.puml` and then sharing an export can leak local file contents. PlantUML itself limits this with security profiles.

## What held up

- 2000 random documents with quotes, backslashes, Unicode, keywords and dots in names save and reopen exactly, once the QA-02/03/19 values are left out.
- 400 random sequences of 40 edits undo to the start and redo to the end exactly.
- Recursive `!define` and `!procedure`, include cycles and self-includes terminate; PlantUML itself overflows its stack on the recursive cases.
- Empty, blank, comment-only, CRLF, deeply nested (60 packages) and Unicode files are handled.
