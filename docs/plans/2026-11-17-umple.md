# Umple: import and export

Status: implemented 2026-11-17.

## 1. Why

[Umple](https://umple.org) is a modelling language: classes, attributes, associations and generalizations are written as text in `.ump` files, next to state machines and method code, and the Umple compiler generates Java, Python, PHP and other languages from them. Its own tools (UmpleOnline, the VS Code extension) already cover text editing, code generation and diagram editing. What fastumpl adds is its layout: an Umple class model opens laid out with few crossings, without dragging boxes by hand.

The design left this open (design §12, "What UMPL means"): fastumpl assumed UML class diagrams, and noted that Umple would only need a reader and writer in `umpl-text`. That is what was built. `.umpl` stays the saved format, so an Umple file is never overwritten.

Export goes the other way: a class diagram drawn in fastumpl can be handed to the Umple compiler to generate code.

## 2. What is built

All in `umpl-text` (no new dependencies), plus the CLI and the editor on top.

```rust
pub fn umple::import(src: &str) -> Parsed;      // never fails; problems carry line and column
pub fn umple::export(doc: &Document) -> String;

Format::Umple                                   // `.ump`, `--to umple`; can_read() is true
```

The importer has its own lexer (`umple/lexer.rs`) because Umple, unlike PlantUML, is free-form: a statement ends with `;` or a `{ … }` block wherever the line breaks fall, and class bodies hold method code in Java, Python and other languages. Strings and comments are single tokens, so braces inside them never unbalance a method body. Code templates (`name <<! … !>>`) are skipped by searching the source for `!>>`, since template text may hold quotes, braces or `//`.

Names are resolved after the whole file is read: Umple class names are global (a namespace only sets the package of generated code) and may be used before they are declared.

## 3. Import

| Umple | Result |
|---|---|
| `class`, `interface`, `enum` | The same element kinds |
| `abstract;` in a class | Abstract class |
| `trait T<…>`, `external X`, `singleton;`, `immutable;` | Class with stereotype `trait`, `external`, `singleton`, `immutable` |
| A class opened again (mixins, such as UmpleOnline's position blocks after `//$?[End_of_model]$?`) | The same element; members are added, comments before it dropped |
| `namespace a.b;` | Nested packages `a`, `b`; following classes go in them |
| `name;`, `Integer id;`, `autounique id;`, `String[] tags;` | `name: String`, `id: Integer`, `id: Integer`, `tags: String[]` (untyped attributes are strings in Umple) |
| `const Integer MAX = 5;` | `MAX: Integer = 5 {static}` |
| `Boolean active = true;` | `active: Boolean = true`; a value with `(` or a line break is dropped, since `(` would make the line read as an operation |
| `Double area = { … }` (derived) | `/area: Double` |
| `public static String f(Integer a) { … }`, with any language bodies | `+f(a: Integer): String {static}`; `void` is left out; bodies are skipped |
| `abstract Integer count();`, interface `void draw(Integer s);` | `count(): Integer {abstract}`, `draw(s: Integer)` |
| `isA A, B;` | Generalization; realization when the parent is an interface (from a class) or a trait |
| A class declared inside another | Subclass of it (Umple's rule); `inner class` and `static class` are plain classes |
| Inline `1 role -- * Other role;`, standalone `association { 1 A -- * B; }` | Association with end labels `"1 role"` and `"* role"`: the left multiplicity is at the left class |
| `->`, `<-` | Directed association towards the arrow |
| `<@>-`, `-<@>` | Composition, the `@` end is the whole |
| `><` | Association |
| `0..1 self spouse;` | Association from the class to itself, the label on both ends |
| `associationClass R { * A; * other B role; … }` | Class `R` with an association to each end class: `A "1" -- "*" R`, `B "1 role" -- "* other" R` |
| `//` and `/* */` comments | Comments on the next class, package or association |
| A name used but never declared | A class, with a problem (`use` files are not read) |

Skipped, with a problem at the line: state machines (in a class or `statemachine`), constraints `[…]`, requirements `req`, mixsets, UmpleRT ports, `use` statements, associations to a trait's type parameter, and anything not understood. Skipped silently, as they only concern generated code or tooling: `generate`, `strictness`, `depend`, `key`, `before`/`after`/`around` code injection, `emit`, tests, tracing, code templates, port connectors, active methods, `position` and `displayColor`.

Umple positions (`position x y w h;`) are not read: their box sizes come from UmpleOnline's font, and at fastumpl's sizes boxes could overlap. The diagram is laid out on open instead, as for PlantUML.

## 4. Export

```
// Shop

// «entity»
class Order {
  abstract;
  isA Entity;
  OrderId id;
  const int count;
  // contains
  1 <@>- 1..* OrderLine lines;
  * -> * Payment;
  // depends on Status
  public Money total() {}
}

namespace billing;

class Payment {}
```

| `.umpl` | Umple |
|---|---|
| Title | `// title` on the first line |
| Package | `namespace a.b;` before its classes; classes outside packages come first |
| Name used in two packages | `pkg_Name` (Umple names are global) |
| Class, abstract class, interface, enum | `class`, `class` with `abstract;`, `interface`, `enum X { A, B }` |
| Stereotype `singleton`, `immutable`, `trait`, `external` | `singleton;`, `immutable;`, `trait X`, `external X` |
| Other stereotypes | `// «stereo»` above the class |
| Attribute `name: Type = v` | `Type name = v;`; `{static}` becomes `const`; visibility is dropped (Umple attributes have none); `T[*]` becomes `T[]` |
| Operation `+f(a: int): T` | `public T f(int a) {}`; abstract ones `public abstract T f(int a);`, interface ones `T f(int a);` |
| Generalization, realization | `isA Parent;` in the child |
| Association, directed, composition | Inline in the class at the `from` end (the other end when `from` is an interface): `1 role -- * Other role;`, `->`, `<@>-` |
| Missing multiplicity | `*`; `1` for the whole of a composition |
| Aggregation | Association with `// aggregation` |
| Relation name | `// name` above the association |
| Dependency | `// depends on X` in the class |
| Note | Its text as comments above each element it is attached to, or where it stands |
| Anything else (an association to an enum, between two interfaces) | `// A -- B` above the element |

Positions are not exported.

## 5. Command line and editor

```
umpl convert model.ump -o model.umpl    # import
umpl convert diagram.umpl -o model.ump  # export; or --to umple
umpl render model.ump -o model.svg      # render, check and stats read .ump directly
```

`fmt` and `tidy` refuse `.ump` files, as they do PlantUML files. In the editor, Open lists `.ump` files; opening one (also by drag and drop, recent files or the command line) imports it as an unsaved diagram named after the file, so Save writes a `.umpl` file. File → Export Umple… is also in the command palette.

### Corpus results

The corpus test was run on the 790 example models in Umple's repository (`umpleonline/umplibrary`: the user manual examples, UmpleOnline's examples and its extra examples):

```
UMPLE_CORPUS=path/to/umplibrary cargo test -p umpl-text --test umple_corpus -- --ignored --nocapture
```

- 790 files, 6711 classes and 9650 relations read in 0.08 s; no panics; 517 files with no problems.
- Every member read has the shape of an attribute or operation (checked with `UMPLE_CORPUS_MEMBERS=1`).
- Problems are what fastumpl does not draw: 235 state machines, 89 requirements, 70 mixsets, 42 constraints, 41 `use` statements, 36 ports, 10 associations to trait parameters, and 30 names declared in other files or missing on purpose (the manual's error examples).
- 31 statements are not understood. All are invalid Umple: role names with hyphens or spaces in models converted from Ecore, stray `{ }` blocks, and the manual's examples of syntax errors.
- Exported again, every model imports with no problems and the same classes; 4 of 9650 relations (between two interfaces) became comments.
- 39 files have no classes: they hold only requirements, comments, mixset features or syntax errors.

Not verified: the exported files have not been run through the Umple compiler itself. They follow the grammar in Umple's repository (`cruise.umple/src/class/umple_classes.grammar` and the files it includes), and fastumpl's importer reads them back cleanly.
