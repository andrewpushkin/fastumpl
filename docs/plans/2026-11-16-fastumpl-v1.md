# fastumpl v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Rust desktop editor that opens, edits and saves `.umpl` UML class diagrams and lays them out automatically with few line crossings.

**Architecture:** Cargo workspace of six crates (`umpl-core`, `umpl-text`, `umpl-layout`, `umpl-draw`, `umpl-cli`, `umpl-app`) as in design section 4. Layout works in whole grid units (1 unit = 8 px). Screen and SVG paint the same shape list.

**Tech Stack:** Rust 1.91.0, egui/eframe 0.33, rfd (GTK 3 dialogs), resvg for PNG. Everything builds and runs in the dev container: `scripts/dev.sh cargo ...`.

**Spec:** `docs/design.md`

## Global Constraints

- All cargo commands run through `scripts/dev.sh` (Ubuntu 26.04 container, Rust 1.91.0).
- `umpl-core`, `umpl-text` and `umpl-layout` have no external dependencies.
- Layout is deterministic: same input gives identical output on every run and thread count (seeded own RNG, ties broken by index).
- Grid unit 8 px. Min gap between boxes 5 units, between layers 10 units. Line width 1.5 px, corner radius 6 px. Box border 1.5 px, radius 4 px.
- Font: DejaVu Sans Mono (regular, bold, oblique, bold oblique), bundled in `assets/fonts`, advance width 0.602 em. Name 14 px bold, members and labels 12 px.
- Score weights: crossing 10, upward-rule violation 20, bend 1, length 0.1 per unit.
- File writes are atomic (temp file in same folder, then rename).

## Decisions taken while planning (my calls, differing from or refining the design)

- Notes are elements of kind `Note`; a note link is relation kind `NoteLink` (`..`). Syntax: `note N1 "text"` and `N1 .. Order`. This puts notes in the `layout` block like any element.
- End annotations: one quoted string per end, `"mult role"`. One word is a multiplicity if it looks like one (`0-9 * . n`), otherwise a role.
- Undo uses "set slot" operations: every `Op` replaces one element/relation/package/root list/title and returns the old value as its inverse.
- Lane spreading is done by the router itself: sharing a lane with another line costs as much as a crossing, except inheritance lines to the same parent, which share for free (this produces the trunk).
- Abstract class names and abstract operations are drawn in italics (DejaVu Sans Mono Oblique faces are bundled); static members are underlined.
- Labels avoid boxes, lines and other labels; lines do not avoid labels (labels are placed after routing).

## Review Focus

1. A file whose relation names an element that does not exist — open it, keep the line as raw text, list a problem; never crash.
2. Cyclic inheritance (`A --|> B`, `B --|> A`) — layout must still terminate and place both.
3. Self-relation (`A --> A`) — router must draw a loop off one side, not a zero-length line.
4. Empty file and file with only a `layout` block — open as empty diagram.
5. Two relations between the same pair of elements — two distinct, non-overlapping lines.

Each has a test in the owning task (Tasks 3, 6, 7, 3, 7).

### Task 1: Workspace and document model (`umpl-core`)

**Files:** `Cargo.toml` (workspace), `crates/umpl-core/src/{lib.rs,model.rs,ops.rs,editor.rs}`

**Interfaces — Produces:**
- `ElementId(u32)`, `RelationId(u32)`, `PackageId(u32)`; `Pos { x: i32, y: i32 }` (grid units).
- `ElementKind { Class, Abstract, Interface, Enum, Note }`; `Visibility { Public, Private, Protected, Package }`.
- `Member { vis: Option<Visibility>, text: String, is_static: bool, is_abstract: bool }` with `fn is_operation(&self) -> bool` (text contains `(`), `fn parse_line(&str) -> Member`, `fn to_line(&self) -> String`.

- `Document { title: Option<String>, elements: BTreeMap<ElementId,Element>, relations: BTreeMap<RelationId,Relation>, packages: BTreeMap<PackageId,Package>, root: Vec<Decl>, trailing_comments: Vec<String> }` with `new_*_id()`, `full_name(ElementId) -> String`, `find(&str) -> Option<ElementId>`, `package_of(Decl) -> Option<PackageId>`.
- `Op { Element(ElementId, Option<Element>), Relation(..), Package(..), Root(Vec<Decl>), Title(Option<String>) }`; `Document::apply(&mut self, Op) -> Op` (returns inverse).
- `Editor { doc, revision: u64 }` with `transact(ops)`, `transact_merge(key: &str, ops)` (merges with previous group of the same key, for drags), `undo() -> bool`, `redo() -> bool`, `can_undo/can_redo`, and helpers `add_element(kind, name, package, pos) -> ElementId`, `delete_elements(&[ElementId])` (also deletes their relations), `rename(ElementId, &str)`, `set_element(ElementId, Element)`, `connect(from, to, kind) -> RelationId`, `set_relation`, `delete_relation`, `move_elements(&[(ElementId, Pos)], merge_key)`.

### Task 2: Lexer and parser (`umpl-text`)

**Files:** `crates/umpl-text/src/{lib.rs,lexer.rs,parser.rs}`

**Interfaces — Produces:** `parse(src: &str) -> Parsed { doc: Document, problems: Vec<Problem> }`, `Problem { line: usize, col: usize, message: String }`.

Grammar (line-oriented, `#` comments attach to the next declaration):
```
diagram "Title"
[abstract] class|interface|enum Name [<<stereo>>] [{ member lines }]   # enum body may be comma-separated
note Name "text"
package name { ... }
A ["end"] ARROW ["end"] B [: name]
layout { Full.Name at x, y }
```
Arrows `--|> ..|> -- --> o-- *-- ..> ..` and their reversed forms `<|-- <|.. <-- --o --* <..`. Unknown/invalid lines become `Decl::Raw` + a `Problem`. A relation to an unknown name is kept as Raw.

### Task 5: Orthogonal router

**Files:** `crates/umpl-layout/src/router.rs`

**Interfaces — Produces:** `route_all(graph, nodes: &[(i32,i32)], groups: &[Rect]) -> Vec<Route>`; `reroute(graph, nodes, routes: &mut [Route], dirty: &[usize])`.

A* over integer grid points, state = (point, direction). Costs: step 1, bend 1 (×3 inside search to prefer straight), crossing a perpendicular occupied point 50, running along a lane already used 50 (free for Hierarchy edges with the same `to`), passing through a box or its border: blocked. Start: boundary points of source box (not corners), first step outward; Hierarchy edges leave the child's top and enter the parent's bottom. Target: any non-corner boundary point of target, entering perpendicular. Order: Hierarchy first, then others by Manhattan distance. Then one rip-up pass: every edge with ≥1 crossing is re-routed with all others fixed; keep if better; repeat up to 3 times. Self-edge: leave right side, return on top.

- [ ] Tests: `straight_line_between_aligned_boxes` (0 bends), `routes_around_obstacle` (never enters the box), `two_parallel_edges_do_not_overlap` (Review Focus 5), `inheritance_siblings_share_trunk`, `self_loop` (Review Focus 3), `deterministic`.
- [ ] Implement, commit.

### Task 6: Layering, ordering, coordinates, packing, candidates

**Files:** `crates/umpl-layout/src/{layering.rs,ordering.rs,coords.rs,place.rs}`

**Interfaces — Produces:** `layout_all(graph, opts: &Options) -> Layout`; `place_new(graph) -> Layout` (only nodes with `pos == None` move); `route_only(graph) -> Layout`; `Options { candidates: usize (default 8), seed: u64, cancel: Option<Arc<AtomicBool>> }`.

- Layering: break hierarchy cycles by DFS; layer(child) ≥ layer(parent)+1 for Hierarchy, Whole above part when acyclic; then relax nodes to minimise Σ|Δlayer| for Assoc/Dep/Note edges (target Δ 0), 10 passes; if a layer's width > 1.6 × total height estimate, push assoc-only nodes down.
- Ordering: dummy nodes for edges spanning >1 layer; barycenter sweeps (24) then adjacent swaps while crossings+same-layer span decrease. Candidate k uses `Rng(seed+k)` for initial order; candidate 0 uses current x order.
- Coordinates: per layer, minimise Σ(x−desired)² under order and gap (pool-adjacent-violators), desired = mean neighbor centre; 8 down/up sweeps; integer snap. Layer gap = 10 + edges-between/3 (cap 20).
- Groups: lay out innermost groups first, then the group as a box in its parent (pad 2, header 3). Components packed in rows toward 16:10.
- Candidates run in `std::thread::scope`, best `Stats::score` wins, ties by index.

- [ ] Tests: `parent_above_child`, `no_overlaps_random_graphs` (50 seeded graphs), `cyclic_inheritance_terminates` (Review Focus 2), `k33_like_minimum_found_small` (exhaustive check on ≤ 8 nodes: crossings equals brute-force best layer order), `groups_contain_members`, `place_new_moves_only_new`, `same_input_same_output`.
- [ ] Implement each file with its tests, commit per file.

### Task 11: App viewer (`umpl-app`)

**Files:** `crates/umpl-app/src/{main.rs,app.rs,view.rs,paint.rs,camera.rs,io.rs}`
